# 版本管理约定

书签匠采用“正式版基线 + 开发版迭代”的双轨版本号。唯一状态源是仓库根目录的 `version.json`。

## 开发版

- 格式为 `主版本.正式版本.开发序号`，例如 `0.1.1`、`0.1.2`。
- 每次完成一项由用户提出、且实际修改产品代码或界面的任务后，开发序号必须加 1。
- 只做解释、检查或讨论而没有修改代码时，不增加版本号。
- 每次增加开发版号时，必须同时更新 `version.json` 和 `CHANGELOG.md`。
- 开发版号只显示在应用前端，不修改安装包、Cargo 或 npm 的正式版元数据。

## 正式版

- 只有用户明确要求“发布正式版”时才创建正式版。
- 正式版可以跨越任意多个开发版；例如 `0.1.1` 至 `0.1.18` 都可属于正式版 `0.1.0` 的开发过程。
- 发布下一个常规正式版时，正式版本加 1、开发序号归零，例如从正式版 `0.1.0` 发布为 `0.2.0`。
- 正式发布时同步 `version.json`、`package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、Cargo 元数据和 `CHANGELOG.md`，并重新生成安装包。
- 主版本号仅在用户明确要求不兼容的大版本发布时增加。

## 每次代码任务的完成清单

1. 开发版最后一位加 1。
2. 在 `CHANGELOG.md` 顶部记录该版本全部用户可见变化。
3. 运行前端构建和相关测试。
4. 用户需要试用时，运行 `npm run tauri:build:dev` 重新生成 Windows EXE/安装包。

## 开发版构建目录

- 所有开发版统一复用 `src-tauri/target-dev`，不按版本号创建新目录。
- 可执行文件固定输出到 `src-tauri/target-dev/release/bookmark-craftsman.exe`。
- 安装包固定输出到 `src-tauri/target-dev/release/bundle/nsis/`。
- 如果可执行文件被正在运行的应用锁定，应关闭占用后重试，不能另建目标目录规避。
